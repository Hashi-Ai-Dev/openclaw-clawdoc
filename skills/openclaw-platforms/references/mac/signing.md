# mac signing (debug builds)

This app is usually built from
[`scripts/package-mac-app.sh`](https://github.com/openclaw/openclaw/blob/main/scripts/package-mac-app.sh),
which now:

- Sets a stable debug bundle identifier: `ai.openclaw.mac.debug`
- Writes the Info.plist with that bundle id (override via
  `BUNDLE_ID=...`)
- Calls
  [`scripts/codesign-mac-app.sh`](https://github.com/openclaw/openclaw/blob/main/scripts/codesign-mac-app.sh)
  to sign the main binary and app bundle so macOS treats each rebuild as
  the same signed bundle and keeps TCC permissions (notifications,
  accessibility, screen recording, mic, speech). For stable
  permissions, use a real signing identity; ad-hoc is opt-in and fragile
  (see `permissions.md`).
- Uses `CODESIGN_TIMESTAMP=auto` by default; it enables trusted
  timestamps for Developer ID signatures. Set `CODESIGN_TIMESTAMP=off`
  to skip timestamping (offline debug builds).

## Local overrides

```bash
# Use a specific Developer ID
CODESIGN_IDENTITY="Developer ID Application: Your Name (TEAMID)" \
  ./scripts/package-mac-app.sh

# Skip timestamping (offline)
CODESIGN_TIMESTAMP=off ./scripts/package-mac-app.sh

# Pin the bundle ID (e.g. for a fork)
BUNDLE_ID=com.example.openclaw ./scripts/package-mac-app.sh
```

## Ad-hoc signing (default)

Without a Developer ID, the script signs with `codesign --sign -` (ad-hoc).
This produces a signed-but-unnotarized app that:

- Runs locally on the developer's machine.
- Does NOT survive macOS quarantine on other machines.
- Loses TCC permissions when the ad-hoc signature changes between
  builds.

Ad-hoc is fine for local development. For TestFlight or distribution,
sign with a real Developer ID and notarize.

## Verify the signature

```bash
codesign -dv --verbose=4 /path/to/OpenClaw.app
spctl -a -t exec -vv /path/to/OpenClaw.app
```

A Developer ID app passes both. An ad-hoc app passes `codesign -dv` but
fails `spctl -a` — that's expected.

## Re-signing a previously-signed app

```bash
codesign --force --deep --sign - /path/to/OpenClaw.app
```

`--force` replaces the existing signature. Use with care — TCC
permissions will be revoked.

## Common issues

- **`replacing existing signature` warning** — the .app was already
  signed. Use `--force` only if you intend to replace.
- **`bundle format is ambiguous`** — the .app has both arm64 and x86_64
  code; this is fine on Apple Silicon but ambiguous on Intel. Verify
  with `file /path/to/OpenClaw.app/Contents/MacOS/*`.
- **`notarization failed`** — usually a hardened-runtime issue.
  Re-sign with `--options runtime`.
- **`developer cannot be verified`** on launch — the app isn't
  notarized. Either notarize or `xattr -dr com.apple.quarantine`.

## Notarization

```bash
# After signing with Developer ID
xcrun notarytool submit /path/to/OpenClaw.dmg \
  --keychain-profile "your-profile" \
  --wait
xcrun stapler staple /path/to/OpenClaw.dmg
```

The `your-profile` keychain item must be set up first via
`xcrun notarytool store-credentials`.

For local development, notarization is not required. For TestFlight,
App Store, or distribution outside your machine, it is mandatory.
